# Coding Agent Prompt — Malware Report AI Analyzer

## Goal
Build a Python script that takes a Trapix/mtriage malware analysis JSON report as input, sends it to the OpenRouter API for AI-powered analysis, and saves the structured result as a new JSON file.

---

## What you must build

A single Python script: `malware_analyzer.py`

### Usage
```
python malware_analyzer.py <path_to_report.json>
```

Example:
```
python malware_analyzer.py report_Lab01-01_20260509_110900.json
```

Output file is saved automatically in the same directory as the input, named:
```
analysis_<original_filename>
```
Example: `analysis_report_Lab01-01_20260509_110900.json`

---

## Input format

The input is a JSON file produced by Trapix/mtriage. It always contains these top-level keys (some may be empty or null):

- `file_name`, `file_path`, `analysis_time`
- `hashes` — md5, sha1, sha256
- `file_size`, `file_type`
- `virustotal` — detection counts, ratio, threat label
- `packer` — is_packed, packer_name, confidence, warnings
- `upx` — unpack success/failure
- `entropy` — file_entropy, section_entropies, high_entropy_sections
- `pe_info` — machine_type, timestamp, imports (dll → list of api names), sections
- `suspicious_apis` — dict of api_name → description
- `iocs` — dict of category → list of values
- `strings` — ascii list, unicode list
- `risk_score_for_IAT`, `risk_level_for_IAT`, `risk_level`

---

## OpenRouter API integration

- Base URL: `https://openrouter.ai/api/v1/chat/completions`
- Auth header: `Authorization: Bearer <OPENROUTER_API_KEY>`
- Additional required headers:
  - `HTTP-Referer: http://localhost` (required by OpenRouter, any valid value works)
  - `X-Title: MalwareAnalyzer` (optional but good practice)
- Model: use `google/gemma-4-31b-it:free` as the primary. If that fails with a 4xx/5xx, fall back to `google/gemma-4-26b-a4b-it:free`, then `meta-llama/llama-3.3-70b-instruct:free`.
- The API key must be read from an environment variable: `OPENROUTER_API_KEY`. If the variable is not set, print a clear error message and exit with code 1.
- Use the standard OpenAI-compatible `/chat/completions` endpoint with `messages` array (system + user roles).
- Set `max_tokens: 4096` and `temperature: 0.2` (low temperature for consistent structured output).

## The AI prompt you must send

### System message (send exactly as written):
```
You are a professional malware analyst. You will receive a raw JSON report generated by a static analysis tool (Trapix/mtriage) for a Windows PE executable. Your job is to analyze this report and produce a structured threat intelligence summary.

You must respond with ONLY a valid JSON object — no markdown, no code fences, no explanation, no preamble. Pure JSON only.

Your response must follow this exact schema:

{
  "analysis_metadata": {
    "file_name": "<from report>",
    "analysis_time": "<from report>",
    "analyzed_by_model": "<model name you are>"
  },
  "hashes": {
    "md5": "<from report>",
    "sha1": "<from report>",
    "sha256": "<from report>"
  },
  "risk_assessment": {
    "overall_risk_level": "<HIGH RISK | MEDIUM RISK | LOW RISK>",
    "risk_justification": "<2-3 sentence explanation of why this risk level was assigned>",
    "virustotal_detection_ratio": "<e.g. 47/75>",
    "virustotal_detection_percent": <number>
  },
  "packing": {
    "is_packed": <true|false>,
    "packer": "<packer name or null>",
    "confidence": "<High | Medium | Low | null>",
    "impact_on_analysis": "<explain how packing affects what can be seen statically>"
  },
  "entropy_analysis": {
    "file_entropy": <number>,
    "overall_suspicious": <true|false>,
    "sections": [
      {
        "name": "<section name>",
        "entropy": <number>,
        "interpretation": "<what this entropy level means for this section>"
      }
    ]
  },
  "import_analysis": {
    "note": "<overall comment on the visible import table and what it reveals>",
    "visible_apis": [
      {
        "api": "<api name>",
        "dll": "<dll name>",
        "role": "<what this API does and why it matters in this context>"
      }
    ],
    "hidden_apis_from_strings": [
      {
        "api": "<api name inferred from string fragments>",
        "likely_use": "<what this API likely does in this malware>"
      }
    ]
  },
  "behavioral_insights": [
    {
      "id": "<B01, B02, ...>",
      "severity": "<CRITICAL | HIGH | MEDIUM | LOW | INFO>",
      "category": "<e.g. Defense Evasion, Persistence, Dropper Behavior, Destructive Payload, Discovery>",
      "title": "<short title>",
      "detail": "<detailed explanation of this behavior, what it means, how it works>",
      "evidence": ["<string or field from the report that supports this finding>"],
      "mitre_attack": "<MITRE ATT&CK technique ID and name, e.g. T1027 - Obfuscated Files or Information>"
    }
  ],
  "suspicious_strings": {
    "critical": ["<strings that are highly alarming>"],
    "high": ["<strings that are suspicious>"],
    "informational": ["<strings that provide context but are not directly malicious>"]
  },
  "iocs": {
    "hashes": {
      "md5": "<from report>",
      "sha1": "<from report>",
      "sha256": "<from report>"
    },
    "file_names": ["<any file names found in strings or report>"],
    "file_paths": ["<any paths found or inferred>"],
    "dlls": ["<DLL names>"],
    "notable_strings": ["<strings that could serve as detection signatures>"]
  },
  "threat_classification": {
    "primary_type": "<e.g. Dropper, Loader, RAT, Ransomware, Worm>",
    "secondary_type": "<if applicable, else null>",
    "evasion_techniques": ["<list of evasion techniques observed>"],
    "capabilities": ["<list of inferred capabilities>"],
    "recommended_actions": ["<list of actionable recommendations for an analyst or defender>"]
  }
}
```

Be thorough. Use all fields in the report — entropy, strings, imports, packer info, VirusTotal results — to derive your findings. Never invent data not present in the report. If a field cannot be determined, use null.
```

### User message:
Send the full content of the input JSON file as a string inside this template:
```
Analyze this Trapix/mtriage malware report and return your analysis as JSON:

<paste the full JSON report content here as a string>
```

## Response handling

1. Call the OpenRouter API with the messages above.
2. Extract the content from `response["choices"][0]["message"]["content"]`.
3. Strip any accidental markdown code fences (` ```json `, ` ``` `) if present — the model may include them despite instructions.
4. Parse the cleaned string as JSON using `json.loads()`.
5. If parsing fails, retry the API call once with the same prompt. If it fails again, save a JSON error file:
```json
{
  "error": true,
  "message": "AI response could not be parsed as valid JSON",
  "raw_response": "<the raw string returned by the model>"
}
```
6. Save the final parsed JSON to the output file with `indent=2` encoding and `utf-8` encoding.

---

## Error handling requirements

Handle and report all of these cases clearly (write them to the output JSON under an `"error"` key, do not crash with an unhandled exception):

| Situation | Behavior |
|---|---|
| `OPENROUTER_API_KEY` not set | Print message, exit code 1 |
| Input file not found | Print message, exit code 1 |
| Input file is not valid JSON | Print message, exit code 1 |
| OpenRouter API returns non-200 | Save error JSON with status code and response body |
| All models fail (primary + fallbacks) | Save error JSON listing all attempted models |
| AI returns unparseable response (after 1 retry) | Save error JSON with raw response |

## Dependencies

Use only the Python standard library plus `requests`. Do not use `openai` SDK or any other third-party package beyond `requests`.

Install instruction to include in a comment at the top of the script:
```python
# Requirements: pip install requests
# Set your API key: export OPENROUTER_API_KEY=your_key_here  (Linux/macOS)
#                   set OPENROUTER_API_KEY=your_key_here      (Windows CMD)
```

---

## Code quality requirements

- The script must work on Python 3.8 and above.
- All logic must be in well-named functions (no single giant main block).
- Suggested function structure:
  - `load_report(path)` — load and validate the input JSON
  - `call_openrouter(report_json, api_key)` — handle API call with model fallback
  - `parse_ai_response(raw_text)` — strip fences and parse JSON, with one retry hook
  - `save_output(data, input_path)` — derive output filename and save
  - `main()` — orchestrate everything, handle sys.argv
- Add a docstring to each function.
- No hardcoded API keys anywhere in the code.
